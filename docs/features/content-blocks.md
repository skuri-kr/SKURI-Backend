# 콘텐츠 작성자 차단 기준

## 목적

익명·실명 UGC에서 사용자가 작성자의 실제 회원 식별자를 알지 못해도 해당 작성자의 콘텐츠를 자신의 화면에서 숨길 수 있게 한다. Friend `member_blocks`와 책임을 분리해 친구 관계·요청·초대·채팅·택시파티 상태는 변경하지 않는다.

## 적용 범위

- 자유게시판 게시글
- 자유게시판 댓글
- 학교 공지 댓글
- 앱 공지 댓글

다음은 적용하지 않는다.

- 채팅 메시지와 채팅방
- 택시파티와 파티 참여·초대
- 친구 관계·요청·즐겨찾기·시간표 공유
- 관리자 조회와 moderation
- 신고 원본·운영 증거
- 공개 Share preview

## 저장 모델

`content_blocks`는 `id`, `blocker_id`, `blocked_id`, 감사 시각을 저장한다.

- `id`: 회원 ID와 무관한 UUID. 외부 해제 API에서만 사용
- `(blocker_id, blocked_id)`: unique
- 단방향: A가 B를 차단해도 B의 화면에는 영향 없음
- 생성 시 blocker/blocked ACTIVE 회원 행을 ID 오름차순으로 함께 잠가 상호 차단과 회원 탈퇴 경합에서 dangling 관계를 막음
- 회원 탈퇴 시 blocker 또는 blocked로 연결된 행을 정리
- 차단 대상이 탈퇴하면 별도 가명 식별자를 남기지 않으므로, 보존된 과거 콘텐츠는 기존 탈퇴 익명화 정책에 따라 `탈퇴한 사용자` 콘텐츠로 다시 보일 수 있음

## API·익명성

- 생성은 `targetType + targetId`만 받는다.
- 서버가 활성 콘텐츠의 작성자를 내부 해석한다.
- 목록은 `blockId`, `label=차단한 사용자`, `blockedAt`만 반환한다.
- 실제 회원 ID, 친구 공개 ID, 닉네임, 학과, 프로필 이미지는 반환하지 않는다.
- 해제는 `blockId`와 현재 사용자 소유 조건으로만 수행하고, 없거나 타인 소유인 경우에도 204로 마스킹한다.

## 조회 정책

- 게시글 목록은 DB 쿼리에서 차단 작성자를 먼저 제외하고 페이지네이션한다.
- 게시글 상세는 기존 `POST_NOT_FOUND`로 마스킹한다.
- 댓글은 자손 연결을 보존하기 위해 제거하지 않고 기존 삭제형 DTO placeholder로 마스킹한다.
- 차단 댓글의 본문·작성자·익명 순번·좋아요 개인화는 노출하지 않는다.
- 차단한 작성자가 이후 게시글·게시판 댓글·학교 공지 답글·앱 공지 댓글/답글을 작성해도, 차단자에게는 인앱 알림·알림 SSE·FCM 푸시를 발송하지 않는다.
- 채팅·택시파티 알림은 콘텐츠 작성자 차단의 적용 대상이 아니다.

## 하위호환

- 기존 Board/Notice/AppNotice 응답 스키마를 변경하지 않는다.
- 새 차단 API는 additive endpoint다.
- 새 차단 관계가 없는 기존 앱 사용자의 결과는 변경 전과 같다.
- 새 앱에서 차단 후 2.1.0 미만 앱으로 내려가도 기존 `isDeleted=true` 댓글 처리 경로로 placeholder를 표시할 수 있다.
- 백엔드를 앱보다 먼저 배포해도 기존 앱은 새 API를 호출하지 않으며 정상 동작한다.

## 검증 기준

- 네 target type에서 같은 작성자를 같은 차단으로 멱등 해석
- 자기 콘텐츠, 삭제·숨김 부모 게시글의 댓글, 예약 상태 앱 공지의 댓글, 탈퇴 작성자 마스킹
- 게시글 필터가 pagination 이전에 적용
- 게시글 상세 404와 조회수 미증가
- 세 댓글 surface의 본문·신원 placeholder와 reply tree 유지
- 차단 처리 뒤 게시판 목록 invalidation, 차단된 답글 대상 composer 해제, 차단 작성자 댓글 알림 미발송
- 목록·해제에서 회원 신원 미노출
- 관리자·신고·채팅·택시파티·Friend 동작 무변경
